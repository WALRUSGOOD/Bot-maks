# SmartSchool — образовательный бот MAX

Бот: https://max.ru/ideya_fiks_232_bot

SmartSchool помогает школьникам: ИИ-репетитор объясняет темы, поиск ищет фрагменты учебных материалов, тесты и прогресс помогают закрепить знания. В режиме репетитора бот сначала ищет материалы и передаёт найденное ИИ; если подходящих фрагментов нет, сообщает, что отвечает без них.

**Важно:** база материалов пока небольшая: заметки по биологии и отдельные открытые фрагменты по химии и английскому. Это не полный комплект учебников 7–11 классов. Доступность бота и корректность ответов в реальном диалоге MAX нужно проверить перед отправкой работы.

## Требования

- Python 3.12 или Docker с Docker Compose.
- Токен собственного бота MAX и, для ИИ, API-ключ Tooken или совместимого провайдера.
- PostgreSQL для сохранения прогресса. Без него локальный сервер временно хранит прогресс в памяти.

ИИ-запросы расходуют баланс провайдера. Ключи в этот репозиторий не включены. Не публикуйте `.env`, токены, пароли и секреты. Если ключ ранее был раскрыт, перевыпустите его.

> **Не запускайте копию с токеном работающего бота, пока не готовы переключить его на эту копию.** При старте в режиме polling программа удаляет существующие webhook-подписки; при запуске в webhook-режиме обновляет их. Это может отключить уже работающую версию на Vercel. Для проверки используйте отдельного тестового бота или сначала согласуйте переключение.

## Подготовка настроек

Скопируйте `.env.example` в `.env`:

```bash
cp .env.example .env
```

В Windows PowerShell:

```powershell
Copy-Item .env.example .env
```

В `.env` задайте `MAX_BOT_TOKEN` и `AI_PROVIDER_KEY`. По умолчанию модель — `glm-5.3-flash`, адрес — `https://tooken.club/v1`. Для учебного запуска с отдельным тестовым ботом оставьте `MAX_MODE=auto` и пустой `MAX_WEBHOOK_URL`: будет использоваться long polling. Если нужен webhook, задайте `MAX_MODE=webhook`, публичный HTTPS-адрес `/webhook` на порту 443 и случайный `MAX_WEBHOOK_SECRET`; обеспечьте HTTPS-прокси. MAX не использует polling одновременно с активной webhook-подпиской.

## Docker: сборка и запуск

Создать образ из Dockerfile:

```bash
docker build -t smartschool-max:latest .
```

Запустить один контейнер (без внешней БД прогресс временно хранится в памяти):

```bash
docker run --name smartschool-bot --env-file .env -p 8000:8000 smartschool-max:latest
```

Полный запуск вместе с PostgreSQL:

```bash
docker compose up -d --build
docker compose ps
docker compose logs -f bot
```

Перед использованием вне локального тестирования установите надёжный `POSTGRES_PASSWORD` в `.env`. Для остановки используйте `docker compose down`: это не удаляет том с данными. Не добавляйте `-v`, если хотите сохранить прогресс.

Проверка процесса:

```bash
curl http://localhost:8000/health
```

Проверка `/health` означает лишь, что сервер отвечает; для проверки всей цепочки отправьте `/start` тестовому боту в MAX и попробуйте меню и ИИ.

Образ в этот архив **не включён**: его можно собрать приведённой командой. В GitHub Actions предусмотрена ручная сборка и сохранение Docker-образа как артефакта (`.github/workflows/docker-image.yml`), если Actions доступен в репозитории.

## Запуск из командной строки

```bash
python -m venv .venv
# Windows PowerShell: .venv\Scripts\Activate.ps1
# Linux/macOS: source .venv/bin/activate
python -m pip install -r requirements.txt
python bot/main.py
```

Пример проверки логики без реального подключения MAX:

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
```

`requirements.txt` фиксирует версии зависимостей для Python 3.12; `requirements.in` содержит диапазоны прямых зависимостей. Тесты не проверяют реальную доставку сообщений и не используют реальные ключи.

## Файлы

- `Dockerfile`, `docker-compose.yml` — сборка и запуск контейнера.
- `requirements.txt`, `requirements.in`, `requirements-dev.txt` — зависимости.
- `bot/`, `core/` — приложение MAX и логика.
- `data/textbooks/` — доступные текстовые фрагменты и указания источников.
- `main.py`, `queue_handlers/`, `vercel.json`, `pyproject.toml` — адаптер Vercel с очередью и PostgreSQL; отличается от непрерывно работающего Docker-приложения и требует конфигурации Vercel и отдельной настройки webhook.
- `tests/` — автоматические тесты.
